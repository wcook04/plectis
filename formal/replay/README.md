# Component replay admission core

`ReplayAdmission.dfy` checks a batch of host-observed component replays against
the supplied registry slice. The slice must be nonempty. For every declared
component, the generated `Check` requires exactly one matching observation;
every observation must match a declared component. This rejects omitted,
duplicate and unknown routes. The check also requires the selected route,
runner and receipt component IDs to agree; the input route, evidence class and
claim-contract identity to match the specification; source and input identities
to remain stable; a parsed receipt with a nonzero byte digest; runner and receipt
statuses and verdicts to be `pass`; normalized result/receipt claim payload
digests to agree; and the exact declared native witness kind to appear in both.

`AdmissionExact` proves soundness and completeness of the executable decision
against the independent quantified `Admission` relation for every finite
registry slice and observation sequence. `UsefulAndAdversarialCases` shows an
attainable accepted row and concrete missing, duplicate, unknown, stale,
mismatched, failed and absent-receipt rejections. The coverage and stale input
mutants in `negative/` weaken the executable decision; the proof checker
requires both to fail. No axiom, assumption or external theorem is used.

The host creates the observation sequence, runs the component, hashes source
and input trees, captures receipt bytes, strictly parses them and normalizes
the public claim payload. The claim and evidence identifiers bind the host
envelope to the declared registry policy; legacy component receipts do not
independently carry those identifiers. A nonzero digest says only that the host
supplied an identity. The host must use a fresh confined output location and
one immutable captured receipt buffer. Host compromise, forged runner result,
dishonest parser, normalization error, unsupported result semantics and an
ordinary component's bare `pass` remain outside the Dafny claim. The result
establishes admission of the observed replay envelope, not correctness of a
component algorithm or authenticity of execution. Native Lean checks retain
their separate runtime requirements.

The generated Python in `src/plectis/replay/_generated/` is called by the
`plectis.replay.accept` adapter through an isolated worker and the shared
sealed-source loader. Dafny, Boogie, Z3, the compiler/runtime, Python and the
host remain trusted. The generated Dafny runtime keeps its upstream MIT
licence. The formal source is Apache-2.0.

## Reproduce

Install the pinned official [Dafny 4.11.0 release](https://github.com/dafny-lang/dafny/releases/tag/v4.11.0).
The macOS arm64 archive SHA-256 is recorded in `metadata.json`. From the
repository root:

```sh
python3 scripts/check/check_replay_kernel.py --dafny /absolute/path/to/dafny
PYTHONPATH=src python3 -m pytest tests/test_replay_kernel.py
```

The checker verifies Dafny, regenerates Python into ignored checkout-local
scratch space, compares every deployed generated byte, and requires both
mutants to fail. Without `--dafny` it checks only recorded source/generated
identities and loader inventory; that mode does not reprove the theorem.
