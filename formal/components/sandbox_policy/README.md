# Sandbox policy decision

`SandboxPolicy.dfy` specifies and implements the sandbox replay's decision over
four normalized action fields. `DecisionExact` proves that each of the six
recognized risk/action/capability/trust tuples receives its specified rule and
that every other tuple receives the fail-closed code. `FullOutputExact` relates
that decision to the exact public verdict and rule strings. In particular,
only the public-fixture write tuple is allowed, and only the mock-database tuple
receives review. The trust-guard mutant removes a required trust check; the
proof and the concrete untrusted-input assertion reject it.

The generated `Evaluate` function is called by
`agent_sandbox_policy_escape_replay._derived_sandbox_policy_verdict` through the
shared isolated component worker. The trusted Python adapter applies the
existing `str(value or "")` normalization. It represents any normalized field
longer than 128 characters by an empty field before invocation: none of the
policy literals is that long, so either value fails the same equality checks.
The original row is retained for reporting. Adapter behavior, the worker,
Dafny, its compiler, Python and the host remain trusted.

This proves the replay's decision table over the supplied fields. It does not
prove that those fields describe a real action, that the policy is adequate,
or that a host sandbox prevents execution or side effects. Existing fixture
and subprocess tests exercise the integration separately.

To recheck the theorem and generated bytes with the pinned Dafny release, use
`python3 scripts/check/check_component_kernels.py --dafny /path/to/dafny`.
The normal hash-binding check does not rerun Dafny.
