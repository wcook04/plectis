Documentation guide

Reading and working with the research

Choose a problem, read its short paper, then follow the argument into the longer record or the supporting source. All eight original Erdős problems remain open. You can contribute a correction, explanation, counterexample or useful failed approach without solving one.

Read

  • A reader’s way in: an introduction without commands or Lean.
  • The papers: the current short papers and longer records.
  • Results and open questions: the stated progress and its limits.
  • Prior work: antecedents, attribution and comparisons.
  • Related problems: connections across the collection.

The short papers explain the main ideas. The long records retain more detail, attempts and unresolved steps. Each result’s own evidence boundary matters: an ordinary mathematical argument and a Lean-checked declaration are different kinds of evidence.

Check

Start with the source map to locate the evidence for a result. Reproducibility gives the checkout and verification commands. External verification explains the selected Comparator interfaces and their limits.

The claim record binds statements to their status and supporting artifacts. Methodology explains the separate roles of Lean, repository checks and mathematical review. A navigation page or a successful repository check does not establish a stronger mathematical statement.

Contribute

Contributing explains how to send an observation or a focused pull request. Credit and stewardship explains how accepted work is attributed, including negative results and corrections. The research commons describes how another researcher can resume and return a longer investigation.

For an AI-assisted session, use the research-shift guide. Coding agents start at the agent entry; the agent workbench documents the detailed tools.

The main guides stay here: reading guide, results, prior art, related problems, source map, reproducibility, methodology, scope and architecture.

The JSON files beside these guides are used by the query tools and website. claims.json records public claim status; methodology.json records the review rules. The remaining indexes help locate evidence. Their filenames stay stable so existing tools and source links continue to work. You can read the papers without opening them.

Generated technical navigation gives a compact view for readers using those indexes.

Files at the repository root

README.md introduces the work and CONTRIBUTING.md explains how to help. AGENTS.md is the shared instruction file for coding agents. Claude Code loads it through CLAUDE.md. Detailed agent rules live in the agent guide, so reading the root does not require a tour of the automation.

lakefile.toml, lake-manifest.json and lean-toolchain configure the Lean project and pin its dependencies. formalization.yaml is the Comparator manifest for selected statements; external verification explains its coverage. CITATION.cff supplies citation metadata, while LICENSE, LICENSES/ and REUSE.toml record the licences.

The code of conduct and security policy live under .github/, alongside CI and contribution forms. Privacy, scope and methodology live here with the other guides.
