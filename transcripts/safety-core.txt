Safety Core is a prototype that I built to give coding agents written rules and check what they do against those rules. It keeps the rules I give coding agents in one file, shows which files each rule applies to, and shows whether a program enforces the rule or the rule is only written down in a visual interface.

This video is a full explanation, first the rulebook and the map, then the full tests, with and without Safety Core, and then how a check can either ask a person or refuse, and then how to look back through one recorded run step by step to see what happened. A coding agent is an AI model that can read files, change code, and run commands in a project. The rulebook is one text file that starts with a few broad commitments called axioms. One axiom is people keep oversight, so people can see what agents do and can stop it or correct it.

Under the axioms are more specific rules called principles, and each principle also names the behavior it forbids called anti-principles. One principle is leave the checks on and the behavior it forbids is switching off a check to finish a job faster or just finish it and work around that check. And a project is files in folders with AI and

the rule book connects each rule to the files that it's about and that connection is called a route. In the visual map I can select a rule and see the files it covers or select a file and see which rules apply to it.

Each rule also has a label that says how it's enforced. A rule with a reminder is text the agent is given when it works on those files. A rule with a check has a small program behind it and the program reads the command the agent is about to run and can refuse it or stop and ask a person first. If you remember the first axiom, that's an actual manifestation of that.

When I edit a rule and rebuild, Safety Core rewrites the instruction files the agents read. The checks run inside Claude Code, the application that connects the AI model to files and commands, as hooks.
