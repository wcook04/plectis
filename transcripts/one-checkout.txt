If you use claw code and codex in the same project folder, then the edits can get mixed together, which can get a little bit annoying. So imagine if claw did fix like a login bug or something, and then codex is halfway through some other change in the same file. Then you want to save the fix now without including the unfinished change. And that saved version is called a git commit. So basically selecting the whole file can end up those changes. So one checkout lets you make that commit from just the edits that you choose. So you or your agent first prepare a patch, so like a list of the exact changes to save, and then you review it, and then one checkout commits that patch. So the unfinished edits stay in your working files, so nobody has to clear them out first. If an older version is still queued for the next commit, it warns you to review that, and then you could otherwise undo the fix, and you still decide which edits belong in the patch.
