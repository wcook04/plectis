# Public boundary

Plectis is a standalone public Python toolkit. Its source code, examples and
records can be inspected and run without access to the private research system
from which it was developed.

JSON contracts, registries, standards, validators and recorded results define
what a component checks. Markdown explains those definitions and links to the
code and evidence; it does not replace them.

Public-safe runtime material may contain:

- source-available Plectis code,
- public-safe copied macro bodies with provenance and bounded claims,
- standards, registries, route or organ identifiers, and schema fields,
- synthetic negative fixtures for forbidden or private material,
- redacted lineage, hashes, omission receipts, and stable error codes,
- command receipts and validation summaries.

Public-safe runtime material must not contain:

- secrets, credentials, tokens, sessions, or local account state,
- raw operator voice or private personal material,
- prompt or provider payload bodies,
- non-public evidence bodies,
- publication, recipient, hosted-release, or production authority surfaces,
- source-mutation, provider-call, or financial-advice authority.

A passing receipt establishes only the result of the named command on its
stated inputs under its stated rules. File and test counts do not establish
product completeness or reliability on different inputs.

For a first run, use the [Quickstart](../../QUICKSTART.md). For publishing a
change, follow the [release discipline](release-discipline.md) and the
[validation guide](../maintainers/validation.md).
